jcode 架构术语表

读 jcode 代码时会反复遇到的术语。术语一旦定义，后续课程统一使用，不再重复解释。Python 类比仅为辅助理解，语义并不完全等价。

一、Rust 工程结构

workspace（工作区）
一个 Cargo.toml 声明的多 crate 项目集合，共享一个 target/ 构建目录和一个 Cargo.lock。jcode 的 workspace 有 84 个成员（1 个根 crate + 83 个子 crate），声明在根 Cargo.toml 的 [workspace] members。类比：Python 的 monorepo。
crate（箱）
Rust 的编译单元，一个 crate = 一个库（lib）或一个二进制（bin），有自己的 Cargo.toml。类比：Python 的发行包。
module（模块）
crate 内部的命名空间组织单位（mod foo; 对应 foo.rs 或 foo/ 目录）。类比：Python 的模块/子包。
re-export / pub use（再导出）
把一个（往往是别的 crate 的）名字在当前位置重新公开，让调用方用一条路径就能访问。jcode 四层洋葱的粘合剂：每层 pub use 下一层的全部模块。类比：__init__.py 里写 from base import *。
feature（特性开关）
Cargo 的条件编译开关（如 embeddings、dev-bins），在 Cargo.toml [features] 声明。类比：Python 的 optional dependency。
cfg(...)（条件编译）
按平台/特性决定某段代码是否参与编译（如 #[cfg(target_os = "macos")]）。类比：if sys.platform == "darwin"，但发生在编译期，其他平台的二进制里根本不含这段代码。

二、读代码必需的 Rust 语法

trait / impl
trait 定义一组行为契约，impl Trait for Type 为某类型实现它。类比：Python 的 ABC / typing.Protocol + 多继承。
dyn Trait（trait object）
通过 trait 引用的多态：Arc<dyn Tool> 是"任何实现了 Tool 的东西"的共享引用。类比：Python 里持有接口类型并调用方法（鸭子类型，但编译期检查）。
Arc<T>
原子引用计数共享指针，多线程安全共享同一份数据。类比：Python 对象的引用计数（所有对象天然共享）。
Mutex / RwLock
互斥锁 / 读写锁，配合 Arc 实现线程安全共享可变状态。类比：threading.Lock / RLock。
async fn / .await
异步函数与等待点。类比：async def / await。
tokio
Rust 最主流的异步运行时（事件循环 + 任务调度 + 网络 IO）。jcode 的 daemon、agent loop 都跑在 tokio 上。类比：asyncio。
channel（mpsc / broadcast）
mpsc = 多生产者单消费者队列；broadcast = 一对多广播（有容量，慢消费者丢消息）。类比：asyncio.Queue / 简易 pub-sub。
Stream / EventStream
异步迭代器（Stream<Item = ...>），逐个产出值。类比：async generator。jcode 里 provider 的流式输出就是 EventStream。
derive 宏（serde）
#[derive(Serialize, Deserialize)] 自动生成序列化代码。serde 类比：pydantic（但编译期生成、零反射）。
clap
Rust 最主流的 CLI 参数解析库（jcode 的 Args/Command 用它定义）。类比：argparse。
Result / anyhow
Result 是 Rust 的错误类型（Ok/Err，类比 Python 异常但显式传播）；anyhow 是应用级"任意错误"的便捷包装。

三、进程与通信

daemon（守护进程）
常驻后台进程。jcode 的 jcode serve 就是 daemon：持有所有会话，客户端进程连上它干活。类比：长期运行的服务器进程。
Unix socket / named pipe
本机进程间通信通道（IPC），不走 TCP。Unix/macOS 用 Unix domain socket，Windows 用命名管道。jcode 的 jcode-transport crate 把两者统一成同一套 API。
NDJSON
Newline-Delimited JSON：每行一个 JSON 对象。jcode 客户端与 daemon 之间的线协议就是 NDJSON（jcode-protocol 定义 Request/ServerEvent）。类比：json.dumps + 每行一条。
client / server 分离
瘦客户端（TUI 窗口、connect REPL、api-bridge）+ 胖服务端（daemon 持有会话与 agent）。一个 daemon 可被多个客户端进程同时连接。

四、jcode 领域术语

agent（代理）
执行一轮对话循环的核心对象：构建 prompt → 调模型 → 解析 → 执行工具 → 循环，直到不再调用工具。
tool / Registry
工具 = agent 可调用的能力（read/bash/edit/webfetch…），实现 Tool trait；Registry 是按名字查工具的注册表（Arc<RwLock<HashMap<String, Arc<dyn Tool>>>>）。
provider
模型服务适配层：Provider trait 统一各家 API（Anthropic/OpenAI/Gemini/Copilot…），MultiProvider 聚合多个实现并做路由/故障转移。
session（会话）
一次对话的持久状态：消息历史、compaction 状态、模型、工作目录等，可跨进程恢复（--resume）。
Bus（总线）
进程内全局广播（tokio broadcast），发布状态类事件（工具开始/完成、todo 更新、子 agent 状态），TUI/server 订阅消费。
DTO
Data Transfer Object：纯数据 + serde 序列化、无 IO 无行为。jcode 把跨 crate 共享的稳定数据结构抽成 jcode-*-types 叶子 crate。
turn（轮）
agent 从"收到用户消息"到"本轮全部工具执行完、生成最终回复"的一次完整循环。
compaction（压缩）
上下文超限时把旧对话压缩成摘要，腾出 token 预算继续工作。
harness（主机架）
指 jcode 这一类"给 LLM 装上手和脚"的框架本身（agent loop + 工具 + TUI + 会话管理的总称）。
